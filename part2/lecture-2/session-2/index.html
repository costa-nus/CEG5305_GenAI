PART A

A brief history of prompting

How did prompting grow from one question to agents? Key message: From text completion to agent, the tech of prompting is more and more complicated to resolve the complicated tasks.

One math question from GSM8K (Cobbe et al., 2021) runs through nineteen methods, from 2020 to 2026. Each method changes one thing and fixes a limit of the method before it. Methods 1 to 10 change the text that the model reads. Methods 11 to 19 add tools, loops, context and memory. Most methods have a slide on what they fix, a slide with code, and a slide on where they are used and what limit remains. The figure lists the nineteen methods in order.

  1. From question to instruction. A direct answer, then an instruction that gives the task and the answer format, then solved examples in the prompt, called in-context learning (Brown et al., 2020).
  2. Think. Chain-of-thought asks for the steps first (Wei et al., 2022). Best-of-n tries many times and needs a checker (Cobbe et al., 2021). Self-consistency lets the tries vote (Wang et al., 2023).
  3. Prompt engineering: from manual to automatic. A system prompt gives the set-up its own role (OpenAI, 2023). Prompt engineering treats a prompt as a program that a person tests. Then an LLM writes and improves the prompt: APE (Zhou et al., 2022), OPRO (Yang et al., 2024) and TextGrad (Yuksekgonul et al., 2024).
  4. Tool use. The model asks for a function and our code runs it (Schick et al., 2023). ReAct puts the model in a loop of thinking and acting (Yao et al., 2023). Reflexion turns a failed try into a lesson (Shinn et al., 2023). MCP is one standard way to connect tools (Anthropic, 2024).
  5. Context engineering and agent. The designer chooses what the model reads at each step (Karpathy, 2025). In agentic context engineering the agent edits its own playbook (Zhang et al., 2025). Then agent design, multi-agent systems (Hadfield et al., 2025) and long-horizon agents with memory (Packer et al., 2023).
  6. What's next? Agents that improve agents (Zhang et al., 2025). People no longer design every part by hand.
PART B

Prompt to think

When does writing more before the answer help? Key message: A reasoning trajectory cannot be trained token by token, thus prompting is the essential tool to steer the reasoning.

This part follows the lecture Inference-time techniques for LLM reasoning by X. Chen (2025). All Part A methods rest on one idea: the model writes some text before it answers. Reasoning models do this after training, as in session 01 (OpenAI, 2024). Tonight the model stays fixed, so we use prompting to trigger and steer the text. There are three directions. A longer chain comes from a better prompt. Many chains come next, and we must choose one answer. A revised chain comes last, and it needs a good check. The part ends with where chain-of-thought helps and where it does not. The figure shows the three directions.

  • Reasoning models and inference-time compute. A model that thinks first can use more computation at inference. The gain gets smaller as the computation grows.
  • Trigger a long chain of thought. Worked examples that contain thoughts (Wei et al., 2022). One instruction with no examples, called zero-shot chain-of-thought (Kojima et al., 2022). The model writes its own examples, called analogical prompting (Yasunaga et al., 2024).
  • Why a chain helps. A harder question gets more steps, so the amount of computation varies. A chain also supports strategies such as decomposition and planning, as in least-to-most prompting (Zhou et al., 2023). Two optional pages give the math: why more thought tokens allow more serial steps (Li et al., 2024).
  • Many chains, then choose. One chain can fail at one step, so we sample many chains. Without a checker that knows the correct answer, we need a rule to choose. Self-consistency takes the answer most chains agree on (Wang et al., 2023). Universal self-consistency asks the model to choose when the answers are free text (Chen et al., 2023).
  • Revise the chain. The model gives feedback on its own answer and improves it: Reflexion (Shinn et al., 2023), Self-Refine (Madaan et al., 2023) and self-debugging for code (Chen et al., 2024). This works when an external check exists, such as running the code. Without one, self-correction can make the answer worse (Huang et al., 2024). The part closes with a design principle: methods that keep scaling with computation last longest (Sutton, 2019).
  • Where chain-of-thought helps. The gains come mainly on math, logic and symbolic tasks (Sprague et al., 2025). The written chain need not show the real reason for the answer (Turpin et al., 2023).

PART C

Prompt as System: Agents and harness

What do the loop and the harness add? Key message: Harness is essential when an agent becomes a complicated system with constraints, tools, failure control, etc.

When one call is not enough, the model runs in a loop. The harness is the code around the model. It runs the model's tool calls, keeps memory and enforces limits. The part first shows what agents can do and where they fail. This gives two challenges: how to give a model abilities beyond chat, and how to control an agent so that a person need not watch it all the time. The next segments define the agent, ask whether each ability should come from training or from the harness, and show that an agent is a whole system. The last two segments cover the context and safety, and the design of the loop itself. The part follows the lecture What are agents? And how do they work? by Fried and Neubig (2026a) and uses pages from two later lectures of the same course (Neubig, 2026; Fried and Neubig, 2026b).

  1. How capable are agents today? A web agent that reads the screen and clicks. The share of research and of company work that moves to agents. A group of agents that wrote a large program, and the same kind of system that deleted a user's inbox. A question for each task: what may an agent do alone, what needs approval, and what is never allowed?
  2. What is an agent? An agent senses its environment and acts on it (Russell and Norvig, 2020). The ReAct loop has three kinds of text: Thought, Action and Observation (Yao et al., 2023). An action is a tool call that the model writes as tokens. A tool has a name, a description and typed arguments. The harness runs the call and puts the result back into the context. The context is the state of the agent. So an agent is a model in a loop. The figure shows one turn of the loop.
  3. Harness or training? A usable agent needs six abilities: accurate tool calling, coherence over a long context, customizability, complex task management, understanding of the environment, and safety. Each can come from training or from harness engineering. Training takes annotation and GPU time and does not generalize to every corner case. A harness changes a prompt, a tool or a skill, and one person can do it. The segment shows the harness part of each ability: checks on tool calls, memory compaction, memory and skills (Zhang et al., 2025), a plan with delegation and verification, MCP, and guardrails with a sandbox. The figure shows the training side and the harness side of each ability.
  4. Agents are systems. Around the model sit the harness, a sandbox, an inference server, a training system and monitoring. Each is separate software and can fail on its own. The figure shows the parts.
  5. Context and safety. The context grows with every call, and each call reads it again. Context compaction replaces old history with a short state; repeated compaction can drift. For safety, the segment names four threat models: a malicious user, prompt injection, agent error and improper means. The defences are a sandbox, fine-grained tokens that limit access, and monitoring.
  6. Multi-agent: When to invoke more agents? A Claude blog post asks when to fold subagents into the main agent loop (Sarkis, 2026). It reports that one agent with skills often does as well as a design with many subagents. Splitting by problem type loses context at each handoff. The post offers three options: merge subagents, call them as tools, or fold them into skills and tools. Its rule: measure, change one thing at a time, and keep what holds up.

Where we got to

The lecture ends with a look back at each setting. Each has a strength and a weakness.

  • Prompting. It needs no training and works with any model you can call. It is fragile: the format of a prompt alone changes the result (Sclar et al., 2024).
  • Chain-of-thought. Large gains on math and symbolic tasks (Sprague et al., 2025). Little gain elsewhere, and it can hurt (Liu et al., 2024). The chain need not show the real reason (Turpin et al., 2023).
  • Reasoning models. They improve with more training and more thinking time (OpenAI, 2024). Few-shot prompts can make them worse (Guo et al., 2025), and they do not always state a hint they used (Y. Chen et al., 2025).
  • Agent and harness. They give facts and actions beyond the weights, and tool feedback can correct errors. They are unreliable across runs (Yao et al., 2024), errors add up on long tasks (Sinha et al., 2026), and a prompt can carry an injection (Greshake et al., 2023).

The lecture question was: How far can a fixed model go? The three key messages answer it. Part A: prompting grew from text completion to agents. Part B: prompting is the essential tool to steer reasoning. Part C: the harness is essential once an agent becomes a complicated system. A fixed model can go far when the input and the loop give what the weights lack: examples, time to reason, tools, feedback and a check.

Practice homework (no course credit)

This is practice homework. It carries no course credit and is not marked. Demo code: two_agent_demo.py · Colab notebook.

Two agents talk. Each agent is a model with its own instructions, and the reply of one is the input of the other. The demo code plays a patient and a counsellor in a first counselling session. It is a class role-play with two simulated roles, not medical advice: do not type your own problems into it.

  1. Run the demo. Get two_agent_demo.py, or open the Colab notebook. It uses the OpenAI Agents SDK and needs an API key for an OpenAI-compatible model; set OPENAI_BASE_URL to use another server. How the course gives access will be posted here.
  2. Predict, then run. Write your predictions with probabilities before you run. For example: will the patient stay in role? How does the talk end?
  3. Choose one piece to change and change only that:
    • The scenario: patient and counsellor, customer and support agent, interviewer and candidate, tutor and student, or two neighbours. Or write your own.
    • The turn limit and the stop word: when does the talk end?
    • The history: does each agent see all earlier messages, or only the last two?
    • A guardrail: a check on one agent's message before the other replies.
    • One sentence of an agent's instructions.
  4. Compare. Run each version 3 times. Compare the number of messages, how the talk ended, role breaks and tokens. Use the same scenario, settings and number of runs for every version. Check that the difference is larger than the spread across your 3 runs. A role break is when an agent steps out of its role; read the transcript, because the count is only a hint. If a result looks too good, read the whole conversation.

What you produce, in at most 300 words: your predictions with probabilities, made before you ran; transcripts of the base run and of your change; counts per version over 3 runs; three findings, ranked; and one result you did not predict, explained.
